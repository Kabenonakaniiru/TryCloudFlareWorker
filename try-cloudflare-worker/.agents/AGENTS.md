## 📍 現在の作業ブランチ (`feature/change_editable_category_on_task`)

- **目的**: タスク（ルール）登録・編集時に、登録されたカテゴリマスタからカテゴリを選択・変更できるようにし、各種リソースの制約・上限やセキュリティを考慮した堅牢化・最適化を行う。
- **実装状況**:
  - バックエンド (`src/handlers/rules.ts`) およびデータベーススキーマでの `groupId` 連携の実装が完了。
  - フロントエンド (`public/rules.html`) にてカテゴリ一覧を `/api/groups` から取得し、ドロップダウンで選択できるように連携済み。
  - **上限を意識した対策**:
    - `ValidationError` の仕組みを導入し、APIハンドラー (`groups.ts`, `rules.ts`, `routes.ts`) で入力値のバリデーションを厳密化。
    - Cloudflare D1 の無料枠リソースなどを意識し、カテゴリ登録件数（最大20件）およびルール登録件数（最大100件）の上限バリデーションを追加。
    - `runDailyLifecycle` 時に毎回 Google OAuth サーバーへアクセストークンをリクエストしていたのを、1回取得して使い回すように最適化（外部 API コールの制限および Workers の CPU 制限時間 10ms の回避）。
    - Google Calendar 認証エラー等の発生時にも、D1 のログ生成や削除などの基本処理が最後まで継続するよう、耐障害性を強化。
  - **セキュリティ・ビルド環境の整理**:
    - 以前のビルド設定 (`tsconfig.client.json`) に起因して `public/dist/` 配下に漏洩していたバックエンド用のJSコードをすべて削除し、ビルドスクリプト (`build.js`) の設定に揃えてクリーンアップ。不要な `tsconfig.client.json` を削除。
  - テストコード（`test/`）もすべて追従し、`npm test` が正常に通過することを確認。


## ⚙️ 技術スタックと構成の概要

- **バックエンド**: Cloudflare Workers
- **データベース**: Cloudflare D1 + Drizzle ORM
- **外部サービス連携**: Google Calendar API（JWT認証、サービスアカウント）
- **タスク更新処理**: Cronトリガーによる `runDailyLifecycle`
- **フロントエンド**: `public/` 配下の静的HTML/CSS/JS (一部 `src/client/admin.ts` から `esbuild` でバンドル)
